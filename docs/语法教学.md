# MC Command Simulator 使用与语法教学

> 适用版本:0.2.0。本教学讲两件事:**脚本怎么写**,以及**界面怎么用**。

MC Command Simulator 是一个离线的《我的世界》基岩版(含网易中国版)指令模拟器,桌面应用。你在编辑器里写一份 `.mcsim` 脚本,程序在没有游戏的情况下把它跑起来:你能看到每条指令的结果、世界里的实体和方块、聊天输出、粒子,还能把命令链导出成纯文本,或者导出成能导入游戏的结构文件。

核心思路只有一句话:**用"声明"搭一个离线的小世界,再用原版指令去操作它。** 声明是本程序自己的写法;指令和游戏里一模一样(基岩版语法,不是 Java 版)。

**怎么读这份文档**

- 第一次用:读第 1、2、3、4 章,照着例子跑一遍,就能写出能用的脚本。
- 查某条指令能不能用、怎么写:看第 5 章。
- 想把场景搬进游戏,或把游戏里的建筑变成脚本:看第 6 章。
- 想让编辑器自动检查结果:看第 7 章。
- 遇到报错:先看第 12 章。
- 不确定模拟器和游戏是否一致:看第 13 章,里面写明了哪些行为已经在游戏里验证过,哪些没有。

**本文的约定**

- 代码块里的内容可以直接粘进编辑器。以 `#` 开头的是注释。
- 界面上的按钮名用粗体,如 **Run once**。界面可以切换中文或英文,切换只改界面文字;**脚本和指令永远是英文**,本文的按钮名用英文界面上的写法。
- "未验证"表示这个行为是按基岩版通行做法或参考文档写的,没有在网易版里逐项核对,以游戏为准。

## 1. 快速上手

### 1.1 先跑起来:第一个脚本

```text
# 一个玩家站在金块上
alice = ent(type=player, pos=(0.5, 65, 0.5), name=alice)
block(type=gold_block, pos=(0, 64, 0))

chain hello at (8, 65, 0):
    /execute as @a at @s if block ~ ~-1 ~ gold_block run tag @s add ready
    cb(conditional=true)
    /say 有人站在金块上
```

操作步骤:

1. 点工具栏的 **New**(或按 `Ctrl+N`)新建一个标签页,把上面的内容粘进编辑器。
2. 工具栏左边有一个"命令链"下拉列表(**Chains**),里面每条链前面都有勾选框,默认全部勾选。本例只有 `hello` 一条,不用动(多条链的用法见 4.6)。
3. 点 **Run once**(或按 `F5`):把已勾选的链里的每个方块依次运行一次。
4. 看右边:**执行记录**逐行写出每条指令的结果;**世界**面板里 alice 多了标签 `ready`;下方的聊天终端出现 `[@] 有人站在金块上`。

启动应用和点 **New** 得到的都是**空文档**,不带示例脚本。

### 1.2 运行方式

| 按钮 | 作用 |
|---|---|
| **Run once**(`F5`) | 把已勾选的链里的每个方块依次运行一次,**忽略命令方块的模式和延迟**。适合快速看结果 |
| **Activate** / **Deactivate** | 激活 / 停用已勾选的链。激活后链按真实的命令方块规则运行:冲击方块要红石、延迟要等刻数、循环方块每隔延迟重复 |
| **Tick +1**(`F6`)/ **Tick +20**(`Shift+F6`) | 让游戏时间前进 1 刻 / 20 刻 |
| **Play** / **Pause** | 连续运行。旁边的"ticks/s"输入框决定每秒跑多少刻,见 1.3 |
| **Reset**(`Shift+F5`) | 把世界恢复成脚本刚写好的样子(包括 `world(...)` 声明的初始状态) |

想看真实的节奏:点 **Activate**,再点 **Tick** 或 **Play**。

### 1.3 自定义播放速度

**Play** 按钮旁边有一个"刻/秒"输入框,默认 20,可以填 1 到 1000 的整数;填了无法识别的内容会回到合法值(空或字母回到 20,超出范围夹到 1 或 1000)。设置会被记住,所有标签页共用。

- 播放时按真实经过的时间换算要执行的刻数,小数部分会累计,所以 5 刻/秒、3 刻/秒这类慢速也是准的。
- 速度很高时,每次最多补 500 刻,避免界面卡死。
- **Tick +1** 和 **Tick +20** 不受影响。

## 2. 脚本基础

脚本文件后缀是 `.mcsim`,也可以打开 `.txt`,是纯文本。一份脚本由三种东西组成:**声明**(搭世界,见第 3 章)、**命令链**(见第 4 章)和**测试块**(见第 7 章)。这一章讲它们共用的规则。

### 2.1 注释

`#` 开头的内容是注释(`#` 前面必须是行首或空格):

```text
# 整行注释
/say hi   # 行尾注释
```

在编辑器里选中几行按 `Ctrl+/`,会给这些行加上或取消 `# `。如果选中的是用 `\` 续行的命令,会自动扩展到整条命令的所有行,不会只注释一半。

### 2.2 一条指令写在多行

行尾写 ` \`,下一行接着写。几行合起来算**一条**逻辑行,只占一个行号:

```text
/execute positioned 2 66 2 \
    rotated as @e[tag=p] positioned ^0.5 ^ ^ \
    run particle minecraft:villager_happy ~ ~ ~
```

- `Shift+Enter`:在光标处插入 ` \` 并换行。
- 工具栏 **Split long**:把超过 100 个字符的 `/execute` 和 `/playanimation` 指令自动拆成续行(**只**拆这两种,其他指令不动)。
- 工具栏 **Join**:把所有续行合回单行。
- 导出指令时会自动去掉 `\`,一条指令仍是一行。
- 续行符 `\` 在编辑器里显示为橙色。续行符前面要有空格,且不能断在单词中间。

### 2.3 位置变量和朝向变量

```text
pos1 = (0, 64, 0)        # 位置:三个数
r1   = rot(90, 0)        # 朝向:rot(偏航, 俯仰),也可以写 (90, 0)
```

- 偏航(`yrot`)可以是任意数,会折算到 -180 到 180;俯仰(`xrot`)必须在 -90 到 90。
- 偏航 0 面向 +z(南),90 面向 -x(西);俯仰 -90 看向上方。
- 变量名由字母、数字、下划线组成。位置、朝向、实体句柄**共用一个名字空间**,重名会报错。

### 2.4 在指令里使用变量

**只有 `${...}` 才会被替换**,指令里的普通文字不会被当成变量:

```text
/tp @e[name=a] ${pos1} ${r1}
/tp @e[name=a] ${pos1.x} ${pos1.y} ${pos1.z} ${r1.yrot} ${r1.xrot}
```

- `${pos1}` 展开成三个坐标,`${r1}` 展开成偏航和俯仰。
- `.x .y .z`、`.yrot .xrot` 取单个分量。
- 导出时已经替换成具体数字,所以导出的文本是纯原版指令。
- 位置变量会记住每个坐标是怎么写的,展开时保持原样:`q = (1.0, 0, 2.5)` 展开成 `1.0 0 2.5`(为什么要紧盯小数点,见 2.5)。

### 2.5 坐标写法与方块中心规则

指令里的坐标和游戏一致:`1 2 3`、相对坐标 `~ ~1 ~`、局部坐标 `^ ^ ^1`,并且支持连写 `~~~`、`^^^0.5`,以及混写 `~~ 0`、`~ 0~`、`~0 0~0` 这样的形式。局部坐标 `^` 不能和世界坐标混用。没有位置的虚拟链,默认在 `(0,0,0)` 执行。

**一条重要规则(已用游戏实测确认)**:基岩版里,指令中**绝对坐标的 x 和 z 如果不带小数点,指的是该方块的中心**。

| 写法 | 实际位置 |
|---|---|
| `0 0 0` | (0.5, 0, 0.5) |
| `0.0 0 0.0` | 正好是 (0, 0, 0) |
| `~ ~ ~`、`^ ^ ^1` | 不受影响 |

y 不受这条规则影响。模拟器对 `positioned`、`facing`、`tp`、`summon`、`particle` 等所有读坐标的指令都按这条规则执行。想要精确位置,写成 `2.0`、`-3.0`。

**声明也遵循同一条规则**:`ent(pos=(1, 2, 3))` 的 x、z 不带小数点,所以实体在 (1.5, 2, 3.5);写成 `(1.0, 2, 3.0)` 才是精确的 (1, 2, 3)。`block`、`fill`、`chain` 的 `pos`、`region`、`spawn` 是方块坐标,不受影响。

命令方块里的 `~ ~ ~` 以命令方块的**中心**为原点(已确认)。

## 3. 声明语法

声明写在脚本里的任意位置(不缩进),模拟开始时按它们建立世界。

### 3.1 参数名简写

声明里的这三个参数名可以写短的,**长的写法照常能用**,同一条里不能同时写两种:

| 简写 | 全名 | 含义 |
|---|---|---|
| `pos` | `position` | 位置 |
| `rot` | `rotation` | 朝向 |
| `comp` | `components` | 物品组件(JSON) |

### 3.2 实体 ent

```text
stand1 = ent(type=armor_stand, pos=pos1, rot=r1, name="a", tags=["first"])
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `type` | 是 | 实体 id,可省略 `minecraft:` |
| `pos` | 是 | 位置:`(x, y, z)` 或位置变量 |
| `rot` | 否 | `(偏航, 俯仰)`、`rot(...)` 或朝向变量,默认 `(0, 0)` |
| `name` | 否 | 游戏里的名牌,**可以重复** |
| `tags` | 否 | 标签列表,如 `["a", "b"]` |
| `selected` | 否 | 仅玩家,选中的快捷栏格子 0 到 8 |

**句柄**:`stand1 = ent(...)` 左边的 `stand1` 只在编辑器里用来指向"这一个实体"(比如给它放物品),**不会出现在导出的指令里**,也不是选择器。指令里要精确选中某个实体,请自己给它加标签:`tags=["first"]`,再用 `@e[tag=first]`。

### 3.3 方块 block

```text
block(type=lever, pos=(0, 0, 0), states=["open_bit"=true])
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `type` | 是 | 方块 id |
| `pos` | 是 | 位置 |
| `states` | 否 | 方块状态,值可以是 `true/false`、整数或带引号的字符串 |
| `nbt` | 否 | 方块实体数据,见 3.5 |

没写的方块状态不会自动补默认值。条件里要求某个没设置过的状态,会判为不匹配。

### 3.4 批量方块 fill

一整块相同的方块,不用逐个写 `block(...)`:

```text
fill(type=stone, from=(0, 0, 0), to=(9, 4, 9), states=[...])
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `type` | 是 | 方块 id |
| `from`、`to` | 是 | 两个对角,顺序任意 |
| `states` | 否 | 方块状态,同 `block` |

范围检查和 `block` 一样:超出 `region` 会报错。

### 3.5 方块实体数据 nbt

`block(...)` 可以带 `nbt=`,用文本形式的 NBT(SNBT)写方块实体数据,比如告示牌的文字:

```text
block(type=oak_sign, pos=(1, 2, 3), nbt={id:"Sign",FrontText:{Text:"hi"}})
```

- 数字带后缀:`1b` 字节、`1s` 短整、`1` 整数、`1L` 长整、`1.5f` 浮点、`1.5d` 双精度。
- 数组写成 `[B;1,2]`、`[I;1,2]`、`[L;1,2]`;`true` / `false` 是字节。
- 字符串里的双引号写成 `\u0022`。

方块实体数据会原样保存,导出 `.mcstructure` 和 `.bdx` 时都会写回。

### 3.6 物品 item

```text
alice = ent(type=player, pos=(0, 0, 0), name=alice, selected=2)
block(type=chest, pos=(5, 0, 0))
item(target=alice, slot=slot.hotbar, index=0, type=diamond, count=5)
item(target=alice, slot=slot.weapon.mainhand, type=diamond_sword)
item(target=(5, 0, 0), slot=slot.container, index=3, type=apple, count=16)
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `target` | 是 | 实体句柄,或容器方块的位置 |
| `slot` | 是 | 槽位名 |
| `type` | 是 | 物品 id |
| `index` | 否 | 槽位序号 |
| `count` | 否 | 数量 |
| `data` | 否 | 数据值 |
| `comp` | 否 | 组件 JSON,如 `comp={"minecraft:item_lock":{"mode":"lock_in_slot"}}` |

可用槽位:`slot.hotbar`(0-8)、`slot.inventory`(0-26)、`slot.enderchest`(0-26,仅玩家)、`slot.container`(按容器大小)、`slot.armor.head/chest/legs/feet/body`、`slot.weapon.mainhand/offhand`。玩家的 `slot.weapon.mainhand` 就是当前选中的快捷栏格子。

### 3.7 区域 region

```text
region(from=(0, 0, 0), to=(20, 20, 20))
```

限定模拟的范围,范围外的方块访问会报错(不会当成空气)。不写时默认 x、z 为 -64 到 64,y 为 -64 到 320。导出整个场景为结构时,所有声明也必须在 `region` 内(见 6.4)。

### 3.8 世界状态 world

```text
world(time=night, weather=rain, difficulty=hard, spawn=(0, 64, 0), seed=123)
```

| 参数 | 说明 |
|---|---|
| `time` | 开局的**一天内**时间:刻数,或 `day / noon / sunset / night / midnight / sunrise` |
| `weather` | `clear`、`rain`、`thunder` |
| `difficulty` | `peaceful`、`easy`、`normal`、`hard` |
| `spawn` | 世界出生点,位置或位置变量 |
| `seed` | 随机数种子,影响 `@r` 和 `scoreboard players random` |

所有参数都可选,整个脚本最多写一条 `world(...)`。不写时:时间 0(早上 6:00)、晴天、普通难度。**Reset 会回到这里写的状态**,所以测试里想固定初始条件就写它。

## 4. 命令链与命令方块

### 4.1 链的写法

```text
chain gate(pos=pos1, facing=south, rot=rot(90, 0)):
    /say first
    cb(facing=east)
    /say second
    /say third
```

旧写法 `chain 名称 at 位置:` 仍然可用。

| 参数 | 说明 |
|---|---|
| `pos` | 链第一个方块的位置。**不写就是"虚拟链"**:不在世界里放方块,所有指令在 `(0,0,0)` 执行 |
| `facing` | `up/down/north/south/east/west`,默认 `east`,必须配合 `pos` |
| `rot` | 执行朝向,影响 `^` 和 `rotated`,默认 `(0, 0)` |

**每个方块有自己的位置**:第 N 个方块在前一个方块沿它朝向的下一格。`cb(facing=...)` 能让这个方块之后的链拐弯。每个方块在**自己的方块中心** `(x+0.5, y, z+0.5)` 执行。

### 4.2 缩进决定指令属于哪条链

这是最容易出错的地方:

- `chain ...:` 下面**缩进**的 `/指令` 和 `cb(...)`,属于它上面最近的那条 `chain`。
- **不缩进**的 `/指令` 和 `cb(...)` 不属于任何 `chain`,它们都归入一条隐式的链,名字叫 `main`。整个脚本里所有不缩进的指令(不管分散在哪几处)合并成**同一条** `main` 链,按出现顺序排列。
- 如果 `chain` 头的下一行就是不缩进的指令,编辑器会提示"没有缩进,所以不属于这条链",提醒你多半是忘了缩进。

```text
/say 我在 main 里            # 不缩进 → main 链
chain a:
    /say 我在 a 里          # 缩进 → a 链
/say 我也在 main 里          # 不缩进 → 仍然是 main 链(接在上面那条后面)
```

隐式的 `main` 出现之后再写 `chain main:` 会报"重复的链"。要自己定义 `main` 时,把 `chain main(...)` 写在所有不缩进指令的前面,不缩进的指令会自动并进去。

### 4.3 命令方块属性 cb

`cb(...)` 写在它要修饰的那条指令**前面**,下面必须紧跟一条指令:

```text
cb(mode=imp, power=needs_redstone)
/execute ...

cb(mode=cha, conditional=true, delay=20)
/say ...

cb(mode=rep, power=always_on, delay=0, first_tick=true)
/scoreboard players add timer sys 1
```

| 参数 | 取值 |
|---|---|
| `mode` | `imp`(冲击)、`cha`(连锁)、`rep`(循环)。写 `type=` 会被拒绝 |
| `conditional` | `true` / `false` |
| `power` | `needs_redstone` / `always_on`。冲击和循环默认前者,连锁默认后者 |
| `delay` | 延迟刻数(整数) |
| `first_tick` | `true` / `false`。命令块的"首刻执行":循环方块带延迟时,通电后先立刻执行一次,之后每隔延迟执行 |
| `facing` | 同链的 `facing`,改变这个方块之后的走向 |

### 4.4 main 链是什么样的命令方块

`main` 没有 `pos`,是"虚拟链":不在世界里放方块,所有指令在 `(0,0,0)` 执行,没有执行者。其中**第一条是冲击方块**(需要红石),**第二条起是连锁方块**(保持开启)。`cb(...)` 在链外也能用,它修饰紧跟在它下面的那条不缩进指令:

```text
cb(mode=rep, power=always_on, delay=20)
/say 每秒一次                       # main 的第一条:循环方块,每 20 刻
/scoreboard players add timer sys 1  # 连锁方块
```

限制:只有 `main` 的**第一条**能写 `mode=imp` 或 `mode=rep`;`cb(facing=...)` 对没有 `pos` 的 `main` 没有实际作用。想让这些指令真的放进世界,请写完整的 `chain 名字(pos=...):`。

### 4.5 跨链触发

游戏里命令链靠**物理相邻**连接,和你把它们写在哪条链里无关。一个方块执行完,会触发它朝向的下一格,只要那一格现在是**连锁命令方块**。所以链 a 最后一个方块朝向链 b 的入口,b 会接着执行。用 `/setblock` 或 `/fill` 把目标格换掉,链就断了。

### 4.6 同时运行多条链与导出指令

工具栏左边的"命令链 N/总数"(**Chains**)是一个**下拉勾选列表**,列出脚本里的所有链(包括 `main`),每条前面有勾选框:

- **Run once**、**Activate**、**Deactivate**、**Export commands**、**Export manifest**,都作用于**已勾选的所有链**,按它们在脚本里出现的顺序处理。
- 列表里有两个按钮:**全选**(全部勾上)和**反选**(勾上的取消、没勾的勾上)。
- 默认所有链都是勾选的,新写出来的链也默认勾选;每个标签页各自记住自己的勾选。
- 想"同时运行所有链":全选,点 **Activate**,再点 **Tick** 或 **Play**,所有链在同一刻里一起走。想只跑几条,就只勾那几条。

**导出**:**Export commands** 导出纯原版指令文本(变量已替换,续行已合并),**Export manifest** 导出带命令方块属性的清单。只勾一条时文件内容就是这条链;勾多条时,指令导出为 `chains.txt`,每条链前面加一行 `# chain 名字`;清单导出为 `chains.manifest.txt`,每条链保留自己的 `# chain ...` 开头。

在 `test` 块里则用 `activate a`、`activate b`、`run c` 逐条写(见第 7 章)。

## 5. 指令参考

脚本里以 `/` 开头的行是指令,写在 `chain` 下面的缩进里(不缩进的归入 `main`,见 4.2)。终端输入框里也可以直接输入指令试。

### 5.1 选择器

- **类型**:`@a @e @p @r @s @n`。`@r` 不写 `type` 时只在玩家里选;随机数带种子,默认固定,可用 `world(seed=123)` 修改,重置后序列重新开始。
- **参数**:`name type tag family x y z r rm dx dy dz c scores hasitem haspermission l lm m rx rxm ry rym`。
- `type`、`name`、`tag`、`family` 可重复并可用 `!` 取反;`tag=` 表示没有标签,`tag=!` 表示至少有一个标签。
- `scores={目标=范围}`,范围支持 `1..5`、`..5`、`5..`、`!3`。
- `c` 可为负数(取最远的)。
- `dx dy dz` 按实体碰撞箱判断,整数原点覆盖整个方块;碰撞箱表和 `family` 表只覆盖常见实体,表外的实体按一个点处理,`family` 则明确报错。
- 同一个参数重复写会报错(`type`、`name`、`tag`、`family`、`hasitem` 除外)。

```text
@e[type=armor_stand,tag=first]
@a[hasitem={item=diamond,quantity=5..,location=slot.hotbar}]
@n[name="wiki:fmbe"]
@e[scores={n=1..5},r=10]
```

### 5.2 已支持的指令一览

| 类别 | 指令 |
|---|---|
| 执行与选择 | `execute`(`as at in positioned rotated facing align anchored if/unless run`) `testfor` `testforblock` `testforblocks` |
| 实体 | `summon` `kill` `tag`(`add remove list`) `tp`/`teleport` `effect` `playanimation` |
| 方块与区域 | `setblock` `fill` `clone` |
| 物品 | `give` `clear` `replaceitem` `enchant` |
| 记分与规则 | `scoreboard` `gamerule` |
| 玩家 | `gamemode` `xp` `inputpermission` `kick` `list` `spawnpoint` `clearspawnpoint` |
| 聊天与屏幕 | `say` `tell`(`msg` `w`) `tellraw` `title` `titleraw` |
| 世界 | `time` `weather` `difficulty` `daylock` `setworldspawn` `tickingarea` |
| 只记录 | `particle` `playsound` `stopsound` `structure`(只做保存、加载、删除的结构库操作,见 5.11 和 6.1) |

"只记录"指:参数会被校验、执行记录里会出现,但不产生声音、粒子画面以外的世界变化。粒子由 **Particles** 面板显示(见 9.1)。

### 5.3 执行与测试类指令

`execute` 支持 `as at in positioned rotated facing align anchored if unless run`。

- `anchored eyes` 和 `facing entity ... eyes` 支持常见实体的眼高;表外的实体明确报错。
- `execute in nether` 和 `execute in the_end` **只接受语法,仍在主世界执行**,执行记录里会给出提示。模拟器目前只有一个维度(主世界)。
- **`execute if/unless ...` 可以不带 `run`**:这时它只返回成功或失败,常用来给下一个有条件连锁方块做门控,条件成立就成功、不成立就失败。`execute as @a` 这类没有条件的分支后面不带 `run` 仍然是语法错误。
- **`run` 后面可以接任何基岩版命令**:有语法表的命令检查语法;已知但还没有语法表的命令只检查命令名;不存在的命令名报"Unknown command"。命令太多时错误提示写"expected a command name",不再列一长串。

```text
/execute as @a at @s if block ~ ~-1 ~ gold_block run tag @s add ready
/execute as @e[type=tnt] at @s run damage @a[r=4] 9 entity_explosion
```

最后一条里的 `damage` 属于"已知但尚未实现"的命令:语法会被检查,运行时记为"尚未实现",不会让整条 `execute` 失败,也不影响其他分支。

`testfor`、`testforblock`、`testforblocks` 用来检查结果。`testforblocks` 比较两个区域的方块是否一致:

```text
/testforblocks 0 0 0 1 0 0 10 0 0          # 完全相同才成功
/testforblocks 0 0 0 1 0 0 10 0 0 masked   # 忽略源区域里的空气
```

### 5.4 实体类指令

`summon`、`kill`、`tag`、`tp`/`teleport`、`effect`、`playanimation`(见第 10 章)。

**`summon`**:`minecraft:` 命名空间下不存在的实体 id(比如拼错的 `zombe`)会失败并提示 `Unknown entity type`,不会生成实体;其他命名空间(如 `wiki:custom`)原样接受。

**`tag`**:`/tag @e[name=a] add first`、`remove`、`list`。带引号的标签名会去掉引号。

**`tp` 的各种写法**:

```text
/tp @s 0 65 0
/tp @s 0 65 0 90 0                     # 带偏航和俯仰
/tp @s 0 65 0 facing 5 65 5            # 朝向某个位置
/tp @s 0 65 0 facing @e[tag=target]    # 朝向某个实体
/tp @s @e[tag=target]                  # 传送到实体
/tp @s 0 65 0 true                     # checkForBlocks
```

`checkForBlocks=true` 时目的地脚下或头部有方块则失败(按"方块不是空气"粗略判断,未验证)。

### 5.5 方块与区域指令

`setblock`、`fill`、`clone`。`/setblock` 对一个相同的方块是否失败按"失败"处理(未验证)。

### 5.6 物品与附魔

`give`、`clear`、`replaceitem`、`enchant`。

**`/enchant`**:

```text
/enchant @s sharpness 3      # 给主手物品附魔
/enchant @s sharpness 6      # 失败:上限是 5
```

- 检查等级上限。
- 检查互斥:已有锋利时再附魔亡灵杀手失败;同一附魔再次附魔是覆盖等级。
- 数字 id 0 到 37 可用,其余新附魔(如 `wind_burst`)只能写名字。
- **暂不检查**"这个附魔能不能用在这件物品上"。
- 数据表在 `src/engine/enchant-data.ts`,没在网易版验证,不一致请改表。

### 5.7 记分板

```text
/scoreboard objectives add n dummy 显示名
/scoreboard objectives list
/scoreboard objectives setdisplay sidebar n descending
/scoreboard players add alice n 1
/scoreboard players list n
/scoreboard players test alice n 1 *
/scoreboard players random alice n 1 10    # 使用带种子的随机数
```

支持 `objectives list`、`objectives setdisplay <list|sidebar|belowname> [目标] [ascending|descending]`、`objectives add ... dummy [显示名]`、`players list [目标]`、`players test <目标> <记分项> <min|*> [max|*]`、`players random <目标> <记分项> <min> <max>`。Scoreboard 面板显示各显示槽位和所有记分项(见 9.3)。

### 5.8 玩家类指令

```text
/gamemode creative @a        # 也可写 survival adventure spectator default 或 s c a d 或数字
/xp 10 @s                    # 加 10 点经验;/xp 3L 加 3 级;/xp -2L 减 2 级
/inputpermission set @a movement disabled
/kick @a[name=bob] 原因      # 把玩家移出世界,Reset 后回来
/list
```

**出生点**:

```text
/setworldspawn 10 64 -3
/setworldspawn              # 用执行位置(取整)
/spawnpoint @a[name=alice] 7 8 9
/spawnpoint @a[name=alice]  # 用该玩家当前位置
/clearspawnpoint @a[name=alice]
```

### 5.9 聊天与屏幕指令

`say`、`tell`(`msg`、`w`)、`tellraw`、`title`、`titleraw`。

```text
/say 大家好
/title @a title 你好
/tell @a[name=bob] 你好
```

**`tell`(私信)** 按网易版实际显示的样子输出:接收方看到斜体的"悄悄地对你说",发送方看到"你悄悄地对某人说"。上面的例子里,终端里 bob 收到 `<alice> alice whispers to you: 你好`(后半句斜体),alice 收到 `You whisper to bob: 你好`。由命令方块执行时,发送者显示为 `@`,没有发送方那一行。

### 5.10 世界类指令

**`time`**:设置时间时,**只在当前这一天的 0 到 23999 刻内取值**,不会跳到别的一天。

```text
/time set night        # 当天的 13000 刻
/time set 6000         # 当天的 6000 刻;30000 也会当成当天的 6000
/time add 1000         # 累加,会跨天
/time query daytime    # 一天内的刻数
/time query day        # 第几天
/time query gametime   # 总游戏刻数
```

具名时间对应:`day`=1000、`noon`=6000、`sunset`=12000、`night`=13000、`midnight`=18000、`sunrise`=23000。0 刻显示为 06:00。世界面板最上面一行实时显示时间。

**`daylock`**:锁定昼夜循环(就是把游戏规则 `dodaylightcycle` 设成 false,和 `/gamerule dodaylightcycle` 是同一个开关):

```text
/daylock true     # 时间不再推进
/daylock false
```

**`weather`**:

```text
/weather rain           # 一直下,直到你改
/weather thunder 600    # 600 刻后自动转晴
/weather query
```

**`difficulty`**:`/difficulty hard`,也可以写 `peaceful easy normal hard`、首字母或 0 到 3。

**`tickingarea`**:`/tickingarea add 0 0 0 15 10 15 spawn true`。

### 5.11 只记录的指令

- **`particle`**:参数会被校验,每次执行产生一条粒子事件,由 Particles 面板显示。
- **`playsound`**:`/playsound random.levelup @a`,只校验参数并记录"谁会听到",模拟器没有声音。
- **`stopsound`**:同样只记录。
- **`structure`**:`save`、`load`、`delete` 会操作结构库(见 6.1);动画和 waterlogged 参数只接受、不生效。

### 5.12 已知但尚未实现的指令

这些指令的名字被识别,运行时记为"尚未实现"(脚本里写了也不会改变世界):

- **有语法表,会检查语法**:`damage`(含伤害原因枚举和 `entity <来源>`)、`camera`、`ride`、`event`、`fog`、`loot`、`locate`、`place`、`spreadplayers`、`schedule`。这些语法按基岩版文档和 Wiki 写成,没有在网易版逐条验证。
- **只检查命令名**:其余基岩版命令,如 `allowlist`、`function`、`camerashake` 等。
- **不存在的名字**:报 "Unknown command"。

补全列表里标着 `not implemented` 的就是这类指令。

## 6. 结构与文件转换

这一章讲怎么把脚本里的场景搬进游戏,以及怎么把游戏里的建筑变成脚本。相关操作都在 **Structures** 面板(工具栏打开)。

### 6.1 结构指令 structure

```text
/structure save house 0 0 0 5 5 5
/structure load house 10 0 0
/structure delete house
```

- `save <名字> <from> <to> [includeEntities] [memory|disk] [includeBlocks]`:`disk`(默认)存进"结构库",重置后仍在;`memory` 重置后消失。
- `load <名字> <位置> [旋转] [镜像] [动画] [秒数] [includeEntities] [includeBlocks] [waterlogged] [integrity] [seed]`:放置方块、命令方块(含指令)、容器物品和实体。
- `delete <名字>`。
- 旋转和镜像会变换 `facing_direction`、`cardinal_direction`、`direction`、`weirdo_direction`、`ground_sign_direction`,其他状态原样保留。`integrity` 同种子可复现,但结果和游戏不同。动画和 waterlogged 只接受,不生效。
- 限制:只有主世界;方块状态不补默认值;实体只保存类型、名字、位置、朝向、标签、手持和护甲物品(从文件导入的实体会保留原始 NBT);命令方块的"上次输出"等运行时字段写入默认值。

### 6.2 结构名前缀

结构的完整名字是 `命名空间:名字`,游戏默认命名空间是 `mystructure`。`/structure save|load|delete` 里可以省略它:`house` 和 `mystructure:house` 是同一个结构。写了别的命名空间(如 `other:box`)就原样使用。终端和面板里显示完整名字。

导入 `.mcstructure` 文件时名字取文件名(空格换成下划线),已有同名结构会被直接覆盖。补全会列出结构库和脚本里 `/structure save` 出现过的名字。

### 6.3 导入和导出 .mcstructure

- **Import .mcstructure**:导入 `.mcstructure` 或 `.bdx` 文件进结构库。
- **Export**:把结构库里的一个结构导出成 `.mcstructure`。
- **Delete**:从结构库删除。

文件格式按网易版样本实现(小端 NBT、方块版本 18168865、命令方块版本 45)。

### 6.4 导出整个场景

**Export whole scene** 把脚本**刚加载时的初始场景**(相当于点 **Reset** 之后,不是正在运行的实时状态)导出成一个 `.mcstructure`。内容是能框住所有方块、命令块链、容器和实体的最小长方体;玩家不导出。勾选"同时加入结构库"会同时存进库里。

- 所有 `block`、`fill`、`ent` 和带 `pos` 的链的每个命令块都必须在 `region` 内,否则拒绝导出,并指出是哪一行(点击会跳到那一行)。
- 没有 `pos` 的链(包括 `main`)会自动找位置放:一条朝东的直线,每个命令块之间连续,链的四周(含两端)都是没有方块也没有实体的空位。优先放在已有内容的外框里,放不下才放到外框旁边,仍然必须在 `region` 内。多条这样的链依次摆放,互相留空。`main` 的第一个仍是冲击命令块,需要红石触发。
- 任何一边超过 64 格就拒绝导出(游戏结构方块的上限),提示实际尺寸。
- 场景里什么都没有也会提示。

### 6.5 基准坐标

导出 `.mcstructure` 或 `.bdx` 后,面板会显示"基准坐标 (x, y, z)"。导入游戏时让结构的最小角(x、y、z 都最小的那个方块)落在这个坐标,所有方块的坐标就和 `.mcsim` 里完全一致。

### 6.6 导出 BDX

每个结构有 **Export .bdx** 按钮,另有 **Export whole scene as .bdx**。格式按公开的 BDump v3 规范写:文件头 `BD@` + Brotli(质量 6)压缩的内容;内容是 `BDX\0`、作者名、一串"画笔移动 / 放置方块"的操作,最后以 `XE` 结尾(数字大端,内嵌 NBT 小端)。

- **方块一律带完整方块状态**:状态写成指令语法,如 `["direction"=2,"open_bit"=true,"upside_down_bit"=true]`。所以活板门的朝向、开关、上下翻转,按钮的依附面和按下状态,拉杆的方向和开关,告示牌的朝向,箱子的朝向都不会丢,也不会退化成旧的数据值。
- **方块实体数据不丢**:告示牌(正反面文字、颜色、涂蜡)、旗帜、头颅等;箱子等容器带物品(含附魔);命令块带指令、模式、延迟、条件、是否需要红石、名字、首刻执行、记录输出。
- 空气不写入,也就是说建造时不会清除原有方块。
- **不限尺寸**:BDX 是逐块建造的,不受 64 格限制。"导出整个场景为 .bdx"还会放宽 `region`:超出范围的方块、链节点也会导出;没有位置的链(含 `main`)仍按 6.4 的规则找空位。
- **实体不能存进 BDX**,导出时会提示跳过了几个;想保留实体,用 6.7 的"实体转命令",或者同时导出一份 `.mcstructure`。
- **未验证**:方块名去掉了 `minecraft:` 前缀(其他命名空间保留);NBT 里的 x、y、z 写的是相对画笔起点的坐标;没有签名。如果你的导入器对这些有不同要求,请告诉我。

### 6.7 实体转命令

导出 BDX 时勾选"实体转为命令",会在结构外侧(z 方向之后)放一条命令块链,建造完成后触发一次,把所有实体召唤出来。

- **触发**:链的第一个是冲击命令块(需红石),旁边有一个石头按钮,按一下开始。链用蛇形排布,每行 32 个,行尾朝下一行转弯。
- **自毁**:勾选"命令链用完自毁"(默认开启)时,最后一个命令块用一条 `fill` 把整片辅助区域(含按钮)清成空气。
- **每个实体依次处理**:`summon <类型> ~dx ~dy ~dz <偏航> <俯仰> [事件] ["名字"]`(偏移相对命令块**中心**)。有标签或物品(或附近有同类同名实体)时,再用临时标签 `mcsim_tmp` 精确选中它:加它自己的标签、用 `replaceitem` 放手持和护甲物品,最后移除临时标签。同类同名实体依次处理,不会串标签;位置重叠的会用 `mcsim_old` 做完成标记,链末统一清除。临时标签一律在链结束时清掉,不留下任何标签。
- **常见幼年生物**(牛、猪、羊、鸡、马、猫、狼、兔、僵尸、狐狸等)会带上对应的出生事件(`minecraft:ageable_set_baby` / `minecraft:as_baby`,**未在网易版验证**)。
- **会丢的**:掉落物实体、物品上的附魔和组件、盔甲架姿势、变种和颜色、血量、效果。导出提示里会列出丢了几个。

### 6.8 文件转脚本

**Import file as script**(或结构库里每行的 **To script**)把 `.bdx` / `.mcstructure` 转成 `.mcsim` 脚本:

- **选项**:第一个方块放在哪个坐标(默认 0,0,0,`.mcstructure` 可用文件自带的坐标)、是否把相同方块合并成 `fill(...)`、是否带实体。结果在**新标签页**打开(标记为未保存),脚本顶部的注释写着来源、范围和转换时丢了什么。
- **转换规则**:
  - 方块 → `block(...)` / `fill(...)`。
  - 箱子等容器 → `block` + `item(...)`。
  - 告示牌等方块实体数据 → `block(..., nbt=...)`。
  - 命令块按朝向还原成 `chain`(带 `cb(...)`,含延迟、条件、红石、首刻执行),孤立的命令块各成一条链。
  - 实体(只有 `.mcstructure` 有)→ `ent(...)` + `item(...)`,坐标带小数点保证精确。
- **会丢的**:命令块的自定义名和"记录输出"、没有指令的命令块(写成普通方块)、实体上除类型/位置/朝向/名字/标签/物品之外的数据、含水层。
- **BDX 的限制**:只带数据值的旧方块放置会给出警告并使用默认状态;使用运行时 ID 的 BDX 无法转换。

## 7. 测试块

写脚本时最费时间的是"跑完以后去看一堆表格,确认对不对"。测试块让这件事自动化。

### 7.1 写法

```text
chain count:
    /scoreboard objectives add n dummy
    /scoreboard players add alice n 1
    /tag @a add ready
    /say counted

test counts:
    run count
    expect score alice n == 1
    expect tag @a has ready
    expect chat contains "counted"
    expect entity @a count 1
    expect block 3 0 0 stone
```

- `test 名字:` 开头,**缩进的行**属于这个测试块,遇到不缩进的行结束。
- 测试里的 `/指令` 步骤如果执行失败(比如引用了不存在的记分项),**这个测试就算失败**,并写出是哪条指令、为什么失败。所以初始化指令写错不会再被当成通过。
- **每个测试都从一个全新的世界开始**,互不影响。

### 7.2 步骤

| 写法 | 作用 |
|---|---|
| `run 链名` | 把这条链运行一次(忽略延迟) |
| `activate 链名` / `deactivate 链名` | 激活 / 停用 |
| `tick 20` | 前进 20 刻(最多 100000) |
| `/指令` | 以控制台身份执行一条指令 |
| `expect ...` | 检查一个结果 |

### 7.3 检查

| 写法 | 含义 |
|---|---|
| `expect entity @e[type=fox] count >= 2` | 匹配的实体数量。`count` 和比较符可省略(默认 `==`) |
| `expect score alice n == 1` | 记分。持有者必须只匹配一个对象 |
| `expect block 3 0 0 stone` | 某个位置的方块(坐标只能写整数) |
| `expect tag @a has ready` / `lacks ready` | 所有匹配的实体都有 / 都没有这个标签 |
| `expect chat contains "counted"` | 聊天里出现过这段文字 |
| `expect particles >= 64` | 粒子事件数量 |

比较符:`== != >= <= > <`。

### 7.4 怎么运行

- 工具栏 **Tests** 按钮打开面板,点 **Run all tests**。失败的行会写出"期望什么、实际是什么",点它能跳到脚本里对应的行。
- 面板里每个 `test` 一行,带勾选框。**全选**、**反选**、"运行已勾选 N/M"和每行的"▶"(只运行这一个)。勾选状态按标签页保存,新写的测试默认勾上。
- 命令行:`node src/cli.ts 文件.mcsim --test`,有失败时退出码为 1;`--only a,b` 只跑指定的测试。

## 8. 编辑器功能

### 8.1 自动补全

输入时自动弹出,`Ctrl+Space` 手动弹出。`Tab` 或 `Enter` 接受,`Esc` 关闭,`↑↓` 选择。接受后会接着给出下一个参数的候选。

它知道:

- 全部指令和子命令、枚举值(模式、效果、规则、附魔等);
- 你脚本里的**位置变量、朝向变量、句柄、实体名、标签、记分项、链名、结构名**;
- 选择器参数(输入 `@e[` 就列出参数名,`type=` 之后列出实体 id);
- 声明参数(`ent(` 之后列出还没写过的键);
- 测试块里的步骤。

候选里标着 `not implemented` 的是已知但还没实现的指令。排序会参考:前缀匹配、当前脚本里出现的次数、你以前接受过哪些候选(保存在本机)。

### 8.2 悬停说明和参数提示

- **悬停**:鼠标停在指令名上显示用法;停在参数上显示"这个位置应该填什么";停在声明里的键(如 `type=`)显示含义;停在变量或句柄上显示它的声明。未实现但有语法表的命令会显示用法和 "Not implemented yet: only its syntax is checked."。
- **参数提示**:光标在指令里时,显示还匹配的用法,当前该填的参数高亮。声明里则列出参数名并高亮当前键。
  - 默认显示在编辑器**底部的提示栏**里,不会挡住代码。
  - 脚本区上方的"提示"下拉列表可以改成"行上方浮层"或"关闭",设置会被记住。
  - 浮层模式下按 `Esc` 隐藏提示(光标移动后恢复),`Ctrl+Shift+Space` 随时再显示。

### 8.3 语法检查与错误定位

`/` 指令的语法错误在编辑器里直接标红波浪线,只标出**第一个不合语法的词**(续行、缩进、行尾注释、`${}` 都不影响位置)。点诊断列表或执行记录里的语法错误行,只选中这个词。缺参数时标在最后一个词上。"未知附魔名"这类语义错误仍是整条选中。

### 8.4 语法高亮

- 声明关键字(`ent`、`block`、`chain`、`cb` 等)是函数色;参数名(`pos=`、`rot=`、`type=`、`name=`、`facing=`、`mode=`、`delay=` 等,简写和全称一样)是属性色;`rot(...)` 是函数色。
- 这些颜色在 `名字 = ent(...)`、`chain 名字(...)`、单独一行的声明和 `cb(...)` 里都一样;普通变量赋值(如 `b = rot(90, 0)`、`p = (1, 2, 3)`)保持变量的写法。
- 续行符 `\` 是橙色。

### 8.5 快捷键

| 快捷键 | 作用 |
|---|---|
| `F5` / `Shift+F5` | 运行已勾选的链一次 / 重置模拟 |
| `F6` / `Shift+F6` | 前进 1 刻 / 前进 20 刻 |
| `Ctrl+S` / `Ctrl+Shift+S` | 保存 / 另存为 |
| `Ctrl+O` | 打开 |
| `Ctrl+N` / `Ctrl+W` | 新建标签页 / 关闭标签页 |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 下一个 / 上一个标签页 |
| `Ctrl+/` | 注释或取消注释选中的行 |
| `Tab` / `Shift+Tab` | 缩进 / 减少缩进(4 个空格) |
| `Shift+Enter` | 续行 |
| `Ctrl+F` | 查找替换 |
| `Ctrl+Space` | 手动补全 |
| `Esc` / `Ctrl+Shift+Space` | 隐藏 / 重新显示参数提示 |
| `Ctrl+Z` | 撤销 |

退格在缩进里会一次删掉一个缩进单位(4 个空格);其他位置一次删一个字符。

### 8.6 界面与文件

- **标签页**:每个文件一个标签,可以拖动排序、中键关闭,未保存的标签有圆点。每个标签保留自己的模拟状态。
- **分界线**:所有面板之间的线都能拖动,双击恢复默认。
- **命令链勾选**:工具栏左边的下拉列表,勾选要运行、激活、停用、导出的链,带"全选"和"反选"(见 4.6)。
- **执行记录**:右上角可以按"指令 / 变化 / 粒子"筛选,**Clear** 只清显示,不会删数据(粒子面板和聊天不受影响),Reset 后恢复。
- **世界面板**:最上面一行是时间、天气、难度和出生点;下面是实体表、方块表(第一列是位置)、记分板和检查器。点一行,检查器显示它的物品栏、效果、玩家状态、命令块内容等。
- **聊天 / 终端**:输入框里输入 `/指令` 直接执行,不带 `/` 就是聊天消息。旁边的下拉列表决定谁来执行终端指令(`@s` 是谁)。
- **语言**:标签栏右上角可以切换中文 / 英文,**只影响界面文字**,脚本和指令永远是英文。
- **文件**:读入时会去掉 UTF-8 的 BOM;原文件如果是 Windows 换行(CRLF),保存时会保持 CRLF。保存是"先写临时文件再替换",中途崩溃不会留下写了一半的文件。窗口大小和位置会记住。最近文件如果已经被删除,点击时会提示并可以从列表里移除。

## 9. 面板

工具栏上的面板按钮(Structures、Scoreboard、Particles、FMBE、nx tree、Tests)打开右侧抽屉。Structures 见第 6 章,Tests 见 7.4,FMBE 见第 10 章。

### 9.1 粒子窗口

**Particles** 面板把 `/particle` 的所有结果画成三维的点。

- **多视图**:面板顶部点"+ 新建视图"增加一个视图,所有视图同时显示、上下排开(最大化后自动排成网格),点视图标题旁的"×"关闭(至少留一个)。每个视图有自己的视角、缩放、观察中心、时间窗口、网格设置、范围过滤和选中的粒子,用来同时看世界里不同位置的粒子。视图状态按文档保存,切换面板不会丢。
- **时间窗口**:每个视图可选"全部粒子 / 只看当前刻 / 最近 5 刻 / 最近 20 刻"。
- **旋转和缩放**:拖动旋转,滚轮缩放(0.05 到 200 倍)。红绿蓝三根轴分别是 x、y(向上)、z。
- **网格和坐标数字**:默认 XZ 地面网格,画在观察中心所在的高度,可切换成 XY 或 YZ。线间距自动取 1、2、5、10、20、50……,保证屏幕上不会太密;线在整数坐标(方块边界)上,过原点的线颜色不同,每 10 格的线稍亮,线旁标出世界坐标数字。XZ 网格在"前 / 后 / 左 / 右"视图里会侧着缩成一条线,需要看网格时把平面切到 XY 或 YZ。
- **跳转**:填 x y z 点"跳转"(或回车)把观察中心移到该点;"对准全部"回到自动居中;"对准选中点"跳到被点中的粒子。"前 / 后 / 左 / 右 / 上 / 下"是类似 Blender 小键盘的轴向视图(悬停可看每个视图的屏幕方向)。
- **范围过滤**:勾选"只显示范围内",填中心坐标和半径,范围外的粒子不画;"按当前视图过滤"用当前观察中心填好中心坐标。
- **点击粒子**:单击粒子会圈出它,在画布上和下方显示它的坐标、种类和产生的刻;点空白处取消。拖动不会触发点击。
- **粒子大小固定**:勾选后粒子大小不随滚轮缩放变化;默认仍按透视缩放。
- **最大化**:面板右上角"最大化"让粒子窗口铺满整个窗口(按 `Esc` 或"还原"退出)。

### 9.2 nx tree 面板

**nx tree** 面板生成并验证"nx 树"指令:一条用 `execute` 分支排出点阵的指令,常用来画粒子图案。

- **生成**:填点数 x / y / z、间距、中心点、辅助实体位置、偏航 / 俯仰标签和末端动作(默认是一条 `particle`),面板就生成指令和对应的辅助实体声明。中心坐标输出成 `2.0` 这样的写法,保证中心就是你设置的精确位置(见 2.5)。
- **插入脚本**:**Insert command into script** 把指令写进脚本;**Insert entities into script** 把辅助实体声明写进脚本;也可以复制不带斜杠的文本,或拆成多行。
- **验证**:面板会在模拟器里实际跑一遍,告诉你"共 N 个分支、M 个不同的点,是否正好是期望的点阵"。点数太多(超过上限)时只生成指令,不验证。
- 辅助实体里用船来设置俯仰,因为目标游戏里盔甲架不能设置俯仰。

### 9.3 记分板面板

**Scoreboard** 面板显示各显示槽位(list、sidebar、belowname)和所有记分项。还没有记分项时提示用 `/scoreboard objectives add` 创建。

## 10. FMBE 与 Molang

### 10.1 playanimation

```text
/playanimation @e[tag=wiki:fmbe] animation.player.attack.positions none 0 "v.xrot=35;v.ypos=16;v.scale=1.5;" wiki:setvariable
```

- 引号里是 **Molang**。命令执行时先算一次,之后**每个游戏刻再算一次**,直到表达式 `return` 一个真值才停止。同一个控制器名会替换旧的动画。
- 变量 `v.` 存在每个实体自己身上,`t.` 是每次求值时的临时变量。`math.sin`、`math.cos` 等用**角度制**。
- `q.life_time` 等查询只支持少数几个,未实现的会报错并指出列号。Molang 写错会在诊断里显示行号和位置。
- 同一刻里多个动画按启动顺序依次求值,游戏里的实际顺序没有验证。

### 10.2 FMBE 面板

工具栏的 **FMBE** 按钮,按顺序用:

1. **前置**:一键把 Wiki 的 8 条 `playanimation` 指令作为一条循环链插入脚本,也可以直接在当前模拟里跑一次。
2. **创建狐狸**:填名牌、位置、手持物品,生成场景声明(`ent` + `item`)或 `summon` / `replaceitem` / `tag` 三条指令。
3. **填充物品**:给已有的 FMBE 狐狸换手持物品。
4. **变量**:勾选 `xpos ypos zpos xrot yrot zrot scale xzscale yscale xbasepos ybasepos zbasepos`,生成并应用 `playanimation`。位置类以 1/16 格为单位,旋转是角度。
5. **Molang 控制台**:对选中的实体求值任意 Molang,查看和搜索它的变量。

面板最上面是 **3D 预览**:拖动旋转(向上拖,画面向上转),滚轮缩放,红绿蓝三根轴分别是 x、y(向上)、z。预览按"基础位置 → 缩放 → 绕 X、Z、Y 旋转 → 位置"的顺序计算,是**示意**,游戏里实际怎么摆还取决于客户端对狐狸骨骼的处理。

## 11. 命令行

不打开界面也能检查、运行和测试脚本,适合自动化和让 AI agent 使用。

### 11.1 子命令

在项目目录下用 Node 运行(需要能直接运行 TypeScript 的新版本 Node),或者先 `npm run cli:build` 生成单文件 `dist-cli/mcsim.mjs`,之后只需要 Node 就能用 `node dist-cli/mcsim.mjs ...`(`npm install -g` / `npm link` 后可以直接敲 `mcsim`)。

```text
node src/cli.ts check  文件.mcsim [--json]
node src/cli.ts run    文件.mcsim [链名...] [--chain 链名]... [--all] [--ticks N] [--command "/指令"]... [--state] [--json]
node src/cli.ts test   文件.mcsim [--only a,b] [--json]
node src/cli.ts export 文件.mcsim [链名...] [--chain 链名]... [--all] [--format commands|manifest]
```

文件名写 `-` 表示从标准输入读脚本。

| 子命令 | 作用 |
|---|---|
| `check` | 只检查不运行,输出编辑器会标红的所有问题:解析错误、声明检查和指令语法。每条有行号,有精确位置时还有列号 |
| `run` | 运行链。不写链名时运行第一条;`--all` 运行全部;`--ticks N` 激活后前进 N 刻(不写就是"运行一次");`--command` 在链之后以控制台身份执行指令;`--state` 输出最终的世界状态 |
| `test` | 运行 `test` 块;`--only` 只跑指定的测试 |
| `export` | 导出指令文本或命令块清单,多条链的格式和界面里一样 |

加 `--json` 时输出 JSON,方便程序读取:
- `check`:`{ ok, diagnostics: [{ line, column?, message, span? }] }`
- `run`:`{ ok, errors, ticks, diagnostics, events, world? }`,`events` 是执行记录里的全部事件,`world`(需要 `--state`)包含刻数、时间、天气、实体、方块、记分板和游戏规则;记分板的持有者显示成名字,没有名字的实体显示成 `类型#编号`
- `test`:`{ ok, total, passed, failed, tests: [{ name, line, passed, checks, failures }] }`

**退出码**:0 表示一切正常;1 表示有诊断、有指令报错(执行记录里出现 `[chat/error]`)或有测试失败;2 表示用法错误、找不到文件、找不到链或测试。

### 11.2 让 agent 使用

agent 的循环可以是:写脚本,`check`,有问题就按行号列号修改,再 `test`,最后 `run --state --json` 看结果。

```text
node src/cli.ts check script.mcsim --json
node src/cli.ts test script.mcsim --json
node src/cli.ts run script.mcsim --all --ticks 40 --state --json
```

注意:`check` 比旧写法更严格,它和编辑器标红的范围一致;`run` 和 `test` 只在有解析错误时才拒绝运行,指令语法问题要用 `check` 查。

### 11.3 旧写法

旧的写法仍然可用,行为不变:

```text
node src/cli.ts 文件.mcsim [链名] [--ticks N] [--export commands|manifest]
node src/cli.ts 文件.mcsim --test [--only a,b]
```

运行链(包括 `--ticks`)时,只要有指令报错,退出码就是 1,并在标准错误输出里写出错误条数;测试里的 `/指令` 步骤失败也算测试失败。

## 12. 常见错误与排查

| 现象 | 原因和办法 |
|---|---|
| `Unknown position variable "x"` | `pos=x` 里的 `x` 没有定义,先写 `x = (0, 0, 0)` |
| `"x" is a rotation, expected a position` | 把朝向变量用在了位置上(或反过来) |
| `ent: unknown argument "..."` | 参数名写错了;可用的键见 3.2 |
| `Argument "position" is given twice` | 同一条声明里 `pos` 和 `position` 同时写了 |
| `/xxx is a Bedrock command that is not implemented yet` | 这条指令已知但还没做,脚本里写了也不会改变世界 |
| `Unknown command` | 指令名写错了(没有这个指令) |
| `no targets` | 选择器没选到任何东西,检查名字、标签和类型 |
| `condition not met` | `execute if/unless` 的条件不满足,后面的 `run` 没执行 |
| `cb(type=...) is not supported` | 要写 `mode=imp/cha/rep` |
| `cb(...) is not followed by a command` | `cb(...)` 下面必须紧跟一条指令 |
| 指令跑进了 main 链,不在我写的链里 | 那行指令没有缩进。`chain` 下面的指令必须缩进(4 个空格);编辑器会在 `chain` 头后第一行没缩进时给出提示 |
| 点 **Run once** 什么都没发生 | 命令链下拉列表里一条都没勾选;打开它点"全选" |
| 链没有按预期走到下一个 | 下一格不是连锁命令方块,或朝向没对上;检查 `facing` 和 `mode=cha` |
| 重置后状态变回开头 | 这是正常的:Reset 回到脚本里声明的初始世界(包括 `world(...)`) |
| 粒子位置和游戏差半格 | 绝对坐标不带小数点是方块中心,见 2.5;需要精确位置就写成 `2.0` |
| 测试里的 `score` 失败:"matches N holders" | 持有者必须只匹配一个,换成具体名字 |
| 导出整个场景被拒绝 | 有声明超出 `region`,或某一边超过 64 格;按提示的行号修改(见 6.4) |

## 13. 已验证与未验证

### 13.1 已在网易版确认的行为

- `rotated as` 会复制俯仰角。
- Wiki 的 8 条 FMBE 前置指令可用;`@n` 可用。
- `/tell` 的显示格式(收件人斜体"悄悄地对你说"、发件人"你悄悄地对…说")。
- 指令中绝对坐标 x、z 不带小数点是方块中心(用探测命令实测,三角函数精度和游戏相差不超过 0.01)。
- 命令方块里的 `~ ~ ~` 以方块中心为原点。

### 13.2 按通行做法写的,没有逐项验证

遇到不一致请以游戏为准并告诉我:

- `time` 的具名时间刻数(day=1000 等),以及 0 刻显示为 06:00;
- `/time`、`/weather`、`/difficulty`、`/daylock`、`/spawnpoint` 等指令输出的文字;
- `/daylock` 是否会同时把时间调到白天(目前只改 `dodaylightcycle`);
- `weather` 的 `duration` 单位按"刻"处理,晴天不会随机变天;
- `/enchant` 的数据表,不检查附魔能不能用在这件物品上;
- `/give` 的填充顺序、`/setblock` 对相同方块的处理、游戏规则默认值;
- 命令方块执行时的朝向,`summon` 不带朝向时的默认朝向;
- 同一刻内多个 `playanimation` 的求值顺序;
- `tp` 的 `checkForBlocks` 判断;
- 未实现命令的语法表(`damage`、`camera` 等十条);
- BDX 导出的三点细节(方块名前缀、NBT 坐标、无签名)和实体转命令里的幼年出生事件名;
- 结构 `integrity` 的结果和游戏不同。

### 13.3 当前的限制

- 只有主世界一个维度,`execute in nether|the_end` 只接受语法。
- 声音只记录不播放;粒子只在 Particles 面板里显示。
- 选择器的碰撞箱表和 `family` 表只覆盖常见实体。
- 结构里实体只保存类型、名字、位置、朝向、标签、手持和护甲物品;BDX 完全不保存实体。
- 许多基岩版指令只识别名字,没有实际行为,见 5.12。
